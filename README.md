# QQ 群消息摘要控制台（QQNT Read-only Summary Toolkit）

不打开 QQ，也能舒服地补完所有群消息：本地网页控制台一键扫描 QQNT 数据库副本，生成按话题 / 时间线的 AI 总结，支持 QQ 式群列表、Telegram 式聊天气泡、已读进度、媒体墙和批量导出原图。

**核心原则：本地只读、零聊天操作。** 工具只复制 QQNT 的本地数据库文件做解析，不打开群窗口、不标记 QQ 已读、不使用 QQ 登录协议、不发送消息，也不修改任何 QQ 文件。「自动获取密钥」会**只读地**读取本机 QQ 进程内存以取出数据库密钥（不注入代码、不修改 QQ），是一次性本地操作。导出媒体时优先复制本地 QQ 缓存；缓存缺失的旧式群图片可按 MD5 从腾讯官方图片 CDN 静默补齐。

## 功能

- **一键总结与覆盖中心**：选群（关注群 / 有缺口或最近扫描的群 / 可搜索多选群目录 / 常用群组合 / 手输群号）+ 时间范围，生成话题、时间线、未归类要点和严格待办的 HTML 报告；运行页用 1 天 / 7 天 / 30 天整体与逐群时间表区分“已扫描有消息 / 已扫描无消息 / 无扫描记录”，直接汇总覆盖率、缺失群时、受影响群与最早缺口。覆盖补扫是独立的低优先级串行任务：启动前显示数据库临时空间与磁盘余量，按单群 24 小时块写入检查点，只更新消息与覆盖记录，不调用 LLM、不生成报告、不复制媒体文件，任意长历史均可取消后继续；单块读取失败会保留为明确的重试项，其他块继续执行。
- **消息**：QQ 式群列表（头像、最后一条预览、本工具未查看数），点进去是 Telegram 式气泡聊天；从时间表、报告或媒体钻取时会固定保留群与时间范围，并显示该范围的扫描完整性和返回路径。滚动自动推进本工具的查看进度；右键选中一段消息可单独做 AI 总结。
- **报告可信度**：历史报告可按群、扫描状态和关键词筛选，标记异常范围与可能重复；阅读器分别显示生成时的扫描覆盖和 AI 输入覆盖，避免把“AI 处理完现有消息”误解为“这个时间范围没有漏扫”。
- **媒体**：全部群的图片 / 视频墙，按群、按人、按类型和时间筛选，详细 / 纯图网格 / 瀑布流三种视图；索引不按媒体数量截断，媒体墙按需分批渲染，导出也会分批复用同一个文件夹，不设媒体数量上限。每项可查看前后消息，也可多选批量导出**原始文件**到文件夹。导出时本地缓存优先；缓存缺失的旧式群图片会尝试从腾讯官方图片 CDN 静默下载，全程不打开群、不触发 QQ 已读。新版 NTV2 图片仅凭数据库里的 MD5 无法取得，缺少 `fileid + rkey` 时仍会标为缺失。
- **咒语库（AIGC 群专用）**：每次总结时顺便从 QQ 图片缓存里读出 AI 生成参数（A1111 / Forge / ComfyUI / NovelAI），建成可搜索的 prompt / 模型 / LoRA 库，并记录是谁在哪个群发的。同时自动识别群里的 `kkt` / `kko` / `kky` 和「求tag」「看看原图」这类消息：`kkt` / 求 tag 只匹配文字 prompt 回复，`kko` / `kky` / 看看原图只匹配后续图片或文件回复。配对可信度会明确标注（引用确认 / 作者相符 / 推测），不会把猜测当事实。
  - **结构化筛选**：除自由文字外支持 `tag:` `-tag:`（排除）`model:` `lora:` `sender:` `generator:` `steps>=30` `steps:20..40` `aspect:portrait` `date:2026-07-01..2026-07-31` `has:answer` `no:file` 等，可任意叠加；输入框下方实时显示「理解为…」，打错会提示原因。点卡片上的模型 / LoRA / 发图人即可只看那一类。
  - **导出**：把当前筛选结果导成`图片 + 同名 .txt 咒语`（kohya / sd-scripts 等训练工具通用格式）加 `index.jsonl` / `index.csv`。用内容 md5 记录导出历史，**再次导出只写新增的**，可选「全部重导」；本地没有可用原图时仍会导出已保存的咒语。
  - **覆盖情况**：按月显示有多少图、其中多少已知发图人、哪些月份从没总结过（那些图的发图人仍可通过补跑总结找回），以及「上次来之后新增多少张」。
  - 注意：QQ 默认不下载原图，压缩过的图片读不到参数。在 QQ 设置里开启「自动下载原图」能让之后的图片保留完整参数，这一步比工具本身更关键。
- **自动任务**：设置页显示上次结果、下次运行、系统漏跑次数和关注群共同覆盖到的时间；首页与关注群页可直接发现自动任务尚未补齐的范围。
- **本地消息库**：多次扫描自动去重衔接并永久保留，不按天数自动删除；消息查询使用 SQLite 索引与游标分页，历史增长不会一次性加载到界面。
- **存储页**：分开显示 QQ 原始数据库、QQ 媒体缓存、工具消息库、咒语库、补扫检查点、临时数据库、运行产物和报告导出；逐项显示实际路径、占用与删除影响。QQ 数据、配置和密钥只允许查看位置，工具没有删除入口；大型 QQ 媒体缓存只在手动触发时计算，避免打开页面就长时间扫描磁盘。
- **设置页**：一键自动获取 QQ 数据库密钥（无需手动破解）、配置 QQ 数据库路径（可自动探测）、配置任意 OpenAI 兼容的 LLM（可在线拉取模型列表）、检查更新并一键升级到最新版本。密钥均用 DPAPI 加密存储。
- 夜间模式、图标 / 真实头像开关。

## 环境要求

- **Windows 10 / 11**（依赖 DPAPI 密钥存储与 PowerShell 5.1；Linux / macOS 暂不支持）
- **QQNT 新架构版 QQ**（Windows 9.9.x 及之后，本地数据库为 `nt_qq\nt_db` 下的 SQLCipher 加密 SQLite）。经典架构老版本 QQ（9.7.x 及更早）不支持。
- **Node.js 18+**（`better-sqlite3-multiple-ciphers` 提供预编译二进制，一般无需本地编译环境）
- 可选：任意 OpenAI 兼容的 LLM API（DeepSeek / OpenAI / 本地 Ollama 等），不配置则只做本地统计不做 AI 总结。

## 安装
Download from release,

or

```powershell
git clone https://github.com/peter119lee/chatlens
cd qqnt-readonly-summary-toolkit
npm install
```

双击 `Start-QQ-Console.cmd` 启动本地控制台（浏览器自动打开 `http://127.0.0.1:8321`）。

## 首次配置（控制台「设置」页）

1. **QQ 数据库路径**：点「自动探测」，或手动填 `...\Tencent Files\<你的QQ号>\nt_qq\nt_db`（QQ 设置 → 存储管理可查看文件保存位置）。
2. **NTQQ_DB_KEY**：QQNT 数据库是加密的，需要一把解密密钥。**推荐**：打开并登录 QQ 后，在设置页点「🔑 自动获取密钥」——工具会从本机 QQ 进程内存里读出密钥、用你自己的数据库验证并保存，全程在本机完成（候选很多，可能要几分钟）。若自动获取失败，可参考开源教程 [QQBackup/qq-win-db-key](https://github.com/QQBackup/qq-win-db-key) 手动拿到 key 再粘贴保存。密钥用 Windows DPAPI 加密存在 `%APPDATA%\QQSummaryTools\`，只有当前 Windows 用户能解密，不会进入项目目录或 Git。
3. **LLM（可选）**：填 API 地址与 key，点「获取模型列表」选一个模型即可。
4. 到「关注群」页勾选你常看的群，回「运行」页点「立即总结」。

## 常见问题

- **腾讯能发现我在用这个工具吗？** 消息扫描、报告生成和「自动获取密钥」都只在本机进行，不登录 QQ 协议、不发送消息，也不会打开群或修改 QQ 已读状态。浏览器加载头像，以及媒体导出在本地缓存缺失时尝试补齐旧式群图片，会访问腾讯公开 CDN；腾讯的网络日志因此可能看到请求 IP、时间和所请求的图片标识。工具不会为补图注入 QQ 或调用 QQNT 内部下载接口，这与 NapCat / OneBot 一类接入 QQ 运行环境或登录协议的方案不同。
- **消息内容会被发到哪里？** 默认哪里都不发。只有开启 AI 总结时，消息文本会发送到**你自己配置**的 LLM 服务；介意就不配 LLM key，本地统计功能照常可用。
- **QQ 更新后失效？** QQNT 大版本更新可能改变数据库结构或密钥获取方式，届时需要等待适配。
- **能在 Linux 用吗？** 暂不能（DPAPI / PowerShell 依赖）。QQNT Linux 版数据库结构类似，欢迎 PR 移植。

## 数据与隐私

- 所有产物（消息库 `store\`、扫描产物 `runs\`、报告 `reports\`）都只在本机，均已被 `.gitignore` 排除。
- 咒语库 `store\knowledge.db` 记录图片位置和解析出的生成参数；运行时成功取得且属于咒语库的图片会按 MD5 去重保存到受保护的 `store\media-objects`，所以清理 QQ 缓存或 `runs\` 不会删除这份长期副本。导出历史记在 `store\export-ledger.json`。
- 本地消息库永久保留，不会由扫描任务或存储页自动清理。需要释放空间时请使用控制台「存储」页：临时数据库可安全重建，运行产物和报告导出则会在删除前明确提示影响。
- 控制台只监听 `127.0.0.1`，每次启动生成随机访问令牌，拒绝非本机 Host。
